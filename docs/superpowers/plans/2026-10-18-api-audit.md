# Audit de l'API — plan d'implémentation

> **Pour les agents :** sous-skill requise : superpowers:executing-plans (exécution inline, voulue
> par l'utilisateur). Les étapes se cochent (`- [ ]`).

**Objectif :** retirer de l'API ce qui n'a plus d'appelant, rendre chaque code de statut
explicite pour le RPC, et nettoyer l'index de `shared`.

**Architecture :** on supprime des routes, leurs méthodes de dépôt et leurs tests ; on donne un
code à chaque `c.json` ; on ouvre Knip sur les exports de l'index de `shared`. Aucune
fonctionnalité nouvelle.

**Pile :** Hono 4 (RPC), Vitest, Knip 6, pnpm + Turborepo.

**Spec :** `docs/superpowers/specs/2026-10-18-web-api-design.md` (D295, D309).

## Contraintes globales

- Branche `chore/api-audit`, partant de `origin/main`, dans un **worktree** à part : l'arbre
  principal porte des fichiers non commités de l'utilisateur, on n'y touche pas.
- `GET /stats/periode` **reste** : le web de production (`main`) le lit encore (D295, précision).
  `GET /stats/bilan` reste : le mobile le lit.
- Toute erreur répond `{ erreur }` ; la donnée d'autrui est introuvable (404), jamais interdite.
- Commits en Conventional Commits, en français, sujet en minuscule, 100 caractères au plus.
- Ne jamais pousser sur `main` ; PR, squash.

- [ ] **Étape 3 : retirer les routes**

`apps/api/src/routes/stats.ts` devient :

```ts
import { PERIODES } from "@better-lift/shared";
import { zValidator } from "@hono/zod-validator";
import { Hono } from "hono";
import { z } from "zod";
import { exigerSession, type LireSession } from "../middlewares/session.js";
import type { DepotStats } from "../services/stats.js";

/** Un fuseau IANA que le moteur connaît : un fuseau inventé fausserait tout le découpage. */
const fuseauValide = (f: string) => {
  try {
    new Intl.DateTimeFormat("fr-FR", { timeZone: f });
    return true;
  } catch {
    return false;
  }
};

const requetePeriode = z.object({
  fuseau: z.string().max(64).refine(fuseauValide, "Fuseau inconnu.").default("Europe/Paris"),
  periode: z.enum(PERIODES),
});

/**
 * Les statistiques, derrière une session. `GET /stats` et `/stats/exercices` sont partis
 * (D295) ; `/stats/periode` suit au branchement du nouveau web, qui ne le lit plus.
 */
export function routesStats(depot: DepotStats, lireSession: LireSession) {
  return (
    new Hono()
      .use(exigerSession(lireSession))
      // Le bilan de toujours (D128), pour l'en-tête du Profil du mobile.
      .get("/bilan", async (c) => c.json(await depot.bilan(c.get("userId")), 200))
      // Par période (D125) : lu par le tableau de bord du web de production.
      .get("/periode", zValidator("query", requetePeriode), async (c) => {
        const { fuseau, periode } = c.req.valid("query");
        return c.json(await depot.lirePeriode(c.get("userId"), new Date(), fuseau, periode), 200);
      })
  );
}
```

### Tâche 3 : un code de statut explicite à chaque réponse (D295)

Un `c.json(x)` sans code ne donne au client RPC qu'un type indifférencié ; avec `200`, `res.ok`
rétrécit le type de `res.json()` (doc Hono, « Status code »).

**Fichiers :** `apps/api/src/routes/{exercices,records,routines,seances,preferences,health}.ts`.

- [ ] **Étape 1 : repérer les réponses sans code**

Run : `grep -nE "c\.json\([^)]*\)\)?$|c\.json\(await [^,]*\)\)" apps/api/src/routes/*.ts | grep -v test`

Au 2026-10-18 : `exercices.ts` (liste, détail), `records.ts` (records, historique),
`routines.ts` (liste, détail, `PUT /:id` → `{ id }`), `seances.ts` (liste, précédentes,
détail, et le `POST` idempotent qui rend 200 sur rejeu), `preferences.ts` (lecture, écriture),
`health.ts`.

- [ ] **Étape 2 : ajouter le code**

Chaque succès prend `200` (ou `201` à la création, déjà posé) :

```ts
// avant
.get("/", async (c) => c.json({ routines: await depot.lister(c.get("userId")) }))
// après
.get("/", async (c) => c.json({ routines: await depot.lister(c.get("userId")) }, 200))
```

Pour un ternaire, coder les deux branches :

```ts
return routine ? c.json(routine, 200) : c.json(INTROUVABLE, 404);
```
