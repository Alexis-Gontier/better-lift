# Lot 6 — la séance : plan d'implémentation

> **For agentic workers:** superpowers:executing-plans, exécution inline (choix de l'utilisateur).
> Plan compact : fichiers, interfaces et tests complets ; le code n'y est que pour le délicat.

**Goal :** saisir un entraînement réel sur le mobile, sans jamais le perdre.
**Spec :** [`docs/superpowers/specs/2026-09-24-lot-6-seance-design.md`](../specs/2026-09-24-lot-6-seance-design.md)

## Global Constraints

Celles des lots 4 et 5 (`CLAUDE.md` fait foi), plus :
- **Expo Go seulement** : aucune dépendance native hors SDK. Toute dépendance Expo passe par
  `npx expo install` (jamais de version de mémoire).
- **Émulateur** : l'API se joint en `http://10.0.2.2:3001` ; lancement `npx expo start --android --go`.
- **Toute charge** passe par `formaterCharge`/`lireCharge` avec `SYSTEME_UNITES` du mobile
  (`apps/mobile/lib/unites.ts`).
- **Chrono et repos** : toujours depuis une heure stockée, jamais un compteur incrémental.

Types et fonctions du § 4 de la spec, sauf `seanceSaisie` et `versEnvoi` (PR 2).

n'arme pas de repos ; `secondesEcoulees` ; `reposRestant` décroît, tombe à 0 puis `null` une fois
passé ; ajout/retrait d'exercice et de série ; `modifierSerie`.

# PR 2 — l'API des séances (`feat/lot-6-seance-api`)

# PR 3 — la saisie réelle (`feat/lot-6-seance-hors-ligne`)

### Task 9 : le brouillon sur disque
`npx expo install @react-native-async-storage/async-storage expo-haptics`.
`lib/brouillon.ts` : `lire()`, `ecrire(s)`, `effacer()` sous la clé `better-lift:seance-en-cours`.
Le contexte en mémoire disparaît : `seance.tsx` relit le disque ; chaque modification écrit.
« Démarrer » relit le disque **au moment de l'appui** et propose de reprendre s'il existe.

### Task 10 : la file d'envoi
`lib/file-envoi.ts` : clé `better-lift:seances-a-envoyer`. Logique pure de la file dans `shared`
(`ajouter`, `retirer`, `classerReponse(status) → "envoyee" | "refusee" | "reessayer"`, TDD).
Terminer : brouillon → file → effacer le brouillon → tenter l'envoi → accueil. Refusée → retour
en brouillon avec le message. Relance au démarrage et par un bouton.

### Task 11 : repos et vibration
Bandeau de repos piloté par `reposRestant` ; `Haptics.notificationAsync` à zéro, une seule fois
par repos (mémorisé dans le brouillon).

### Task 12 : clôture

host.exp.exponent` en pleine séance, relance : la séance et le chrono sont intacts** ; mode avion
(`adb shell cmd connectivity airplane-mode enable`) → terminer → séance en file → réseau revenu →
envoyée, une seule fois en base (MCP). `CLAUDE.md`, PR 3, mémoire.
